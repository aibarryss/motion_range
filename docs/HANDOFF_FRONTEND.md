## 1. Как поднять у себя

```bash
git clone https://github.com/aibarryss/motion_range.git
cd motion_range
git checkout feat/game-skeleton
npm install
npm run dev
```

Нужны: **Node.js ≥ 20**, Chrome или Edge, веб-камера, свет перед лицом (не за спиной).

**Если камеры нет или она занята** — добавь к адресу `?input=mock`: игра пойдёт на мыши и клавиатуре, весь UI при этом настоящий.

```bash
npm test           # 78 тестов, ~1 с
npm run typecheck  # tsc по src и по tests
npm run build      # production-сборка в dist/
```

Проверка «всё на месте»: в консоли `npm test` должно быть **7 файлов / 82 теста passed**. Другой номер — значит ветка не та.

## 3. Контракт v0.4 — минимум, который нужен фронтенду

Игра и UI читают **один объект** `FrameInput` (`src/shared/types.ts`). Источник кадров не важен: реальная камера или мок — поля одинаковые.

```ts
interface FrameInput {
  tMs: number
  hands: HandFrame[]          // 0..2; x/y — экранные доли, уже зеркальные
  player: { leanX, duck }
  events: { shoot: boolean }   // true ровно на кадре выстрела
  fire: { state: FireState, heldMs: number }   // 'IDLE' | 'ARMED' | 'FIRE' | 'COOLDOWN'
  diagnostics: Diagnostic[]    // отсортированы block → warn → info
  metrics: { cameraFps, detectFps, poseFps, latencyMs, brightness }
  calibration: CalibrationProfile | null   // пока всегда null
}
```

Полезное:

- **Подсказку выбирает UI, а не vision:** `primaryDiagnostic(frame.diagnostics)` из `src/shared/diagnostics.ts` возвращает ровно одну (самую важную) или `null`.
- **Числа для текста подсказки лежат в `diagnostic.metric`** (`value`, `limit`, `comparator`, `unit`). UI обязан форматировать их из этого поля, а не держать собственную таблицу порогов — иначе подсказки разойдутся со SPEC.
- **`diagnostic.highlight`** говорит, что подсветить на скелете. Скелет рисует vision (`src/vision/handOverlay.ts`), и он же применяет подсветку.
- **Состояние выстрела смотреть в `frame.fire.state`**, а не выводить из `hands[0].gesture`: «готов» и «курок прижат» — это про большой палец, а не про позу кисти.

**Правило изменения контракта:** `src/shared/**` меняется только вдвоём, через PR, и в порядке **SPEC → тест заморозки → `types.ts`**.

## 5. Чего нет и это не баг

- **Щит ладонью** (`Gesture.SHIELD`) в контракте есть, но живая камера его пока не выдаёт — в работе у A (вместе с признаком `palmFrontality`).
- **Из 11 диагностик живая камера выдаёт 2:** `NO_HAND` и `TOO_DARK`. Остальные — в работе у A. В мок-режиме дополнительно есть `LOW_CONFIDENCE` и `TOO_DARK` (клавиши `C` и `L`).
- **`calibration: null`** — появится вместе с настоящим экраном калибровки.
- **`poseFps` = «—»** — PoseLandmarker ещё не подключён, уклонение корпусом ждёт решения.
- **Отчёт по осям пустой** — считается по кадрам распознавания, которых пока не хватает.

## 6. Правила работы в этом репозитории

- Свои задачи — в ветку `feat/game-*`. `main` держим рабочей.
- `src/shared/**` — только через PR и только вдвоём.
- Числа (пороги, длительности, окна) живут **только** в `docs/SPEC_Diagnostics_and_Fire.md` и `src/shared/consts.ts`; везде остальное — ссылки на них, не копии.
- Перед пушем: `npm run typecheck` и `npm test` должны быть зелёными.
- Комментарии и документация — по-русски, объясняем **почему**, а не «что» (что видно из кода).

## 7. Открытые вопросы, где нужно решение B

1. **Правило `SHOOT_TOO_SLOW` осталось без работы.** В механике «прижал большой палец» понятия «слишком медленно» нет: медленное нажатие всё равно стреляет. Варианты: перевести правило на другой признак или оставить 10 правил вместо 11 и поправить счёт в `README`/`docs/PITCH.md`/`docs/ERROR-MODE.md`. Подробнее — `CODE_REVIEW.md`, пункт 8.
2. **Нужно ли в контракт 21 точка руки.** Сейчас скелет рисует vision. Если Signal Doctor должен подсвечивать точки **в панели UI**, в `HandFrame` нужно поле `points` — это изменение контракта (SPEC → тест → `types.ts`). Подробнее — `CODE_REVIEW.md`, пункт 7.
