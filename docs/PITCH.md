# Питч

> Владелец: B. Черновик — Вт вечер, финализация и репетиция — Ср 13:00–14:00.

## Позиционирование (одна фраза)

**«Self-correcting gesture shooter»: браузерная игра, которая объясняет физическую причину каждого сбоя распознавания и в реальном времени учит игрока выполнять жесты так, чтобы камера его понимала.**

Не заявляем «мы первые» — это неправда. Заявляем «мы другие: тренер, а не курсор».

## Конкуренты (мы проверили рынок)

|---|---|---|
| Pug's Hunt (pugshunt.com) | палец-прицел + пинч-выстрел, лидерборд | объяснения причин сбоя, уклонения телом |
| Quak Attack (txb13.itch.io) | палец-прицел + пинч, статичные предупреждения | диагностики конкретного текущего сбоя по признакам |
| POSU! (itch.io) | body-tracking, активация целей телом | не тир, не объясняющая система |

Ключевой тест: если убрать блок «ошибка», у нас остаётся почти то же, что у конкурентов. Поэтому **режим «ошибка» — главная часть демо, а не «ещё одна фича»**.

## Структура 3 минут

| Время | Блок |
|---|---|
| 0:00–0:25 | Проблема + сразу демонстрация сбоя: жест не распознаётся → приложение объясняет причину → исправляем → работает. «Вот в чём продукт» |
| 0:25–1:40 | Живое демо: раунд от старта до финала. Говорим только то, что видно на экране |
| 1:40–2:20 | Твист: 5 жестов схемой; намеренная ошибка → подсказка с числами |
| 2:20–2:45 | Техника: схема потока данных, что взяли из библиотек, что написали сами |
| 2:45–3:00 | Бонусы и итог: своя логика распознавания, звук, рекорды, что дальше |

## Сценарий живого демо (60–90 с)

1. Свет включён, ровный фон, ~70 см от камеры.
2. Прицел пальцем → выстрел прижатием большого пальца (прицел при выстреле не срывается) → щит ладонью → (уклонение, если готово).
3. **Намеренная ошибка** (большой палец прижат неплотно — остался в зоне 0.18–0.25, или тусклый свет) → приложение называет причину и порог → исправляем → мгновенный эффект. Этот шаг продаёт 20 баллов за режим «ошибка».
4. Финал: счёт + Gesture Readiness Report.

Если демо сломалось: одна фраза — «показываю запись» → видео 60 с. Не извиняться, не отлаживать в эфире.

## 6 вероятных вопросов жюри

1. **«Чем это отличается от демо MediaPipe?»** → своя логика: признаки, автомат перехода, временная фильтрация, диагностика с порогами. Демо распознают только статичные позы.
2. **«Почему браузер?»** → ноль установки, открывается по ссылке, работает на любом ноутбуке с камерой.
3. **«Вы обучали модель?»** → нет, и не требовалось по условиям. Наша работа — слой классификации и диагностики поверх трекинга.
4. **«Что если свет плохой / камера слабая?»** → калибровка + 11 конкретных подсказок + облегчённый режим. (показать)
5. **«Насколько это сложно?»** → честно: трекинг — библиотека; сложность в устойчивости (дребезг, гистерезис, нормализация) — это и есть наша работа.
6. **«Что дальше?»** → мобильная камера, мультиплеер-дуэль, лидерборд, адаптивные тренировки.
